# Ошибка: officecli raw-set с XML в двойных кавычках ломается через PowerShell 5.1

- **Дата:** 2026-09-22
- **Автор:** Педагог-методист (комплект opencode-kollegam)
- **Где:** рабочая программа внеурочной деятельности «Лотос» (docx), вставка Приложения 1 через officecli raw-set

## Симптом

При вызове `officecli raw-set <файл> /document --xpath "//w:sectPr" --action insertbefore --xml $xml`, где `$xml` содержал двойные кавычки в атрибутах (`w:val="24"`, `w:ascii="Times New Roman"`), officecli ответил серией `Unrecognized command or argument 'New'` — XML раскололся на отдельные токены, вставка не произошла. Валидация при этом прошла (ничего не изменилось), что создавало ложное впечатление успеха.

## Причина

Известный баг передачи аргументов PowerShell 5.1 в нативные исполняемые файлы: встроенные двойные кавычки внутри аргумента манглируются, аргумент разрезается по пробелам XML (атрибуты `w:ascii="Times New Roman"` разбиваются на `w:ascii=Times`, `New`, `Roman` и т.д.).

## Решение

Заменить двойные кавычки на одинарные во всех XML-атрибутах фрагмента (`w:val='24'`, `w:ascii='Times New Roman'`) — это валидный XML, а аргумент больше не содержит встроенных двойных кавычек. Для больших фрагментов XML генерируется в файл, читается в переменную и дополнительно выполняется `-replace '"', "'"`. После этого `raw-set` успешно вставил заголовок, примечание и таблицу 34×4; `officecli validate` — «Validation passed: no errors found».

## Как предотвратить

- Для `officecli raw-set` через Windows PowerShell всегда формировать XML-фрагменты с одинарными кавычками в атрибутах.
- Альтернатива: передавать команды через `officecli batch --input <json-файл>`, где содержимое не идёт через командную строку (но `raw-set` в списке глаголов batch не гарантирован — проверять `officecli help batch`).
- После любого raw-set выполнять `officecli validate` + контрольный `get/query` на вставленный узел (не доверять одному «raw-set applied»).
